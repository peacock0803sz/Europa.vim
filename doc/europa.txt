*europa.txt*	europa.vim documentation

==============================================================================
INTRODUCTION						*europa-introduction*

Europa.vim turns your Vim/Neovim into a moon of Jupyter: a quiet orbit around
`.ipynb` notebooks, viewed directly inside the editor. It runs on Deno via
denops.vim, gives identical behaviour on both hosts, and keeps the host
Python-free — no `pip install` of plugin dependencies required.

Phase 2 (current) provides read-only viewing and round-trip saving. Opening
a notebook renders each cell with Unicode border decoration and highlights
rich outputs: plain text, streams, tracebacks, JSON, Markdown, and HTML.
Images are shown as text placeholders by default; an experimental Sixel
path is available for terminals that support it.

Kernel connection, cell execution, and cell editing land in Phase 3.

QUICK START~
							*europa-quickstart*
1. Open any `.ipynb` file: >
	:edit path/to/notebook.ipynb
<
2. The buffer is read-only (`modifiable=false`). Each cell is framed by
   `╭─ In [N] ─╮` / `╰─ Out [N] ─╯` decorations.

3. To open an image output in the system image viewer: >
	:EuropaPreviewOutput {cellIdx} {outputIdx}
<
   The cell and output indices appear inside the placeholder line shown in
   the buffer.

4. To save back to disk in canonical `.ipynb` format: >
	:write
<

REQUIREMENTS						*europa-requirements*

EDITOR~
							*europa-requirements-editor*
- Vim 9.1.1646 or later
- Neovim 0.11.3 or later

Either host is fully supported. The plugin uses Vim text properties and
Neovim extmarks respectively behind a common interface.

RUNTIME~
							*europa-requirements-runtime*
- Deno 2.3.0 or later		https://deno.land/
- denops.vim			https://github.com/vim-denops/denops.vim

Deno is the TypeScript runtime that powers Europa.vim. denops.vim is the
bridge between the editor and the Deno process.

OPTIONAL~
							*europa-requirements-optional*
- ImageMagick (`magick` or `convert` on PATH)

  Required only when |g:europa_image_backend| is set to `'sixel'`. Europa
  uses ImageMagick to convert PNG/JPEG data to Sixel escape sequences.

- A Sixel-capable terminal emulator

  WezTerm is the only terminal verified to work with the Sixel opt-in as
  of Phase 2. Ghostty 1.3.1 (standard build) and tmux 3.6a without the
  `sixel` compile flag do not pass Sixel through.

SETUP							*europa-setup*

INSTALLATION~
							*europa-setup-install*
Europa.vim requires denops.vim. Install both with your plugin manager.

lazy.nvim: >
	{
	  "vim-denops/denops.vim",
	  {
	    "peacock0803sz/Europa.vim",
	    ft = "ipynb",
	  },
	}
<
vim-plug: >
	Plug 'vim-denops/denops.vim'
	Plug 'peacock0803sz/Europa.vim'
<
dein.vim: >
	call dein#add('vim-denops/denops.vim')
	call dein#add('peacock0803sz/Europa.vim')
<

DENO~
							*europa-setup-deno*
Install Deno from https://deno.land/ or via your system package manager.
Verify the installation: >
	deno --version
<
Europa.vim does not install Deno automatically.

IMAGEMAGICK (OPTIONAL)~
						*europa-setup-imagemagick*
Needed only for the experimental Sixel backend. Install via your OS package
manager, for example: >
	brew install imagemagick        # macOS
	apt install imagemagick         # Debian / Ubuntu
<
Check that `magick` (or `convert`) is on PATH: >
	magick --version
<

CONFIGURATION						*europa-configuration*

All options are global Vim variables of the form `g:europa_*`. Set them in
your vimrc or init.lua before the plugin loads. Unset options fall back to
the defaults shown below.

RENDERING OPTIONS~
					*europa-configuration-rendering*

*g:europa_image_backend*
	Controls how image outputs are displayed.
	Type: string  Default: `'auto'`

	`'auto'`	Resolves to `'placeholder'` in Phase 2. Terminal
			auto-detection (DA1 query) is added in Phase 3.
	`'placeholder'`	Shows a `[image: png WxH - :EuropaPreviewOutput N M]`
			line. Works in every terminal.
	`'sixel'`	Experimental. Renders images inline via ImageMagick.
			Requires a Sixel-capable terminal and ImageMagick on
			PATH. Falls back to placeholder when either is absent.
	`'kitty_placeholder'`  Reserved for Phase 3.
	`'iterm2_osc1337'`     Reserved for Phase 3.

*g:europa_mime_priority*
	MIME type preference order for outputs that carry multiple
	representations (display_data / execute_result).
	Type: list of strings
	Default: `['image/png', 'image/jpeg', 'text/html', 'text/plain']`

*g:europa_max_output_lines*
	Maximum lines rendered per cell output. Outputs that exceed this
	limit are truncated with a `[... truncated, N more lines]` note.
	Type: integer  Default: `100`

*g:europa_cell_border_chars*
	Unicode characters used to draw cell borders.
	Type: list of 5 strings  Default: `['╭', '─', '╮', '╰', '╯']`

*g:europa_lazy_padding*
	Lines above and below the visible viewport that are pre-rendered
	on open. Larger values trade startup time for smoother scrolling.
	Type: integer  Default: `10`

BEHAVIOUR OPTIONS~
					*europa-configuration-behaviour*

*g:europa_auto_save*
	When `v:true`, write the notebook back to disk automatically on
	`BufLeave`. Not recommended until Phase 3 adds conflict detection.
	Type: boolean  Default: `v:false`

*g:europa_use_default_mappings*
	Reserved for Phase 3. No default mappings are provided in Phase 2.
	Type: boolean  Default: `v:false`

CONNECTION OPTIONS (RESERVED FOR PHASE 3)~
				*europa-configuration-connection*
The following options are parsed by the schema but not acted upon in Phase 2.
They are listed here so users can prepare their configuration in advance.

	`g:europa_connection_mode`      `'auto'` | `'server'` | `'zmq'`
	`g:europa_jupyter_url`          URL of the Jupyter server
	`g:europa_jupyter_token`        Authentication token
	`g:europa_default_kernel`       Default kernel name
	`g:europa_auto_start_kernel`    Auto-start kernel on open
	`g:europa_jupyter_executable`   Path to `jupyter` binary
	`g:europa_python_env_detect`    `'auto'` | `'disabled'`

COMMANDS						*europa-commands*

							*:EuropaOpen*
:EuropaOpen [path]
	Open {path} as a Europa viewer buffer. When {path} is omitted the
	current file (`%`) is used. The buffer is set to `modifiable=false`
	and `conceallevel=0`.

	This command is also triggered automatically by `BufReadCmd` when
	you open any `*.ipynb` file with `:edit`.

							*:EuropaPreviewOutput*
:EuropaPreviewOutput {cellIdx} {outputIdx}
	Write the image output at cell index {cellIdx} and output index
	{outputIdx} to a temporary file and open it with the OS default
	image viewer:
	  macOS   `open`
	  Linux   `xdg-open`
	  Windows `cmd /c start`

	Both arguments are zero-based integers. The placeholder line in the
	buffer shows the exact command to run, for example: >
	  [image: png 640x480 - :EuropaPreviewOutput 3 0]
<
	Only image MIME types (`image/png`, `image/jpeg`) are supported.
	Calling this command on a non-image output prints a message and does
	nothing.

CELL EDITING COMMANDS~
						*europa-commands-editing*

							*:EuropaInsertCell*
:EuropaInsertCell {type} [{position}]
	Insert a new empty cell of {type} (`code`, `markdown`, or `raw`)
	relative to the cell at cursor. {position} is `before` or `after`
	(default `after`).

	:EuropaInsertCell! {type}
		Equivalent to `:EuropaInsertCell {type} before`.

	Example: >
	  :EuropaInsertCell code
	  :EuropaInsertCell markdown after
	  :EuropaInsertCell! raw
<
	See also: |:EuropaDeleteCell|, |:EuropaCellType|,
	          |<Plug>(europa-insert-code)|

							*:EuropaDeleteCell*
:EuropaDeleteCell
	Delete the cell at the cursor position. If this is the last cell,
	the viewer shows an empty-notebook guidance message.

	See also: |:EuropaInsertCell|, |<Plug>(europa-delete-cell)|

						*:EuropaMoveCellUp*
:EuropaMoveCellUp
	Swap the cell at cursor with the cell immediately above it in the
	notebook. No-op with a guidance message if already at the top.

	See also: |:EuropaMoveCellDown|, |<Plug>(europa-cell-up)|

						*:EuropaMoveCellDown*
:EuropaMoveCellDown
	Swap the cell at cursor with the cell immediately below it in the
	notebook. No-op with a guidance message if already at the bottom.

	See also: |:EuropaMoveCellUp|, |<Plug>(europa-cell-down)|

							*:EuropaSplitCell*
:EuropaSplitCell
	Split the cell at cursor into two cells at the current line.

	When called from a viewer buffer, the split point is resolved
	relative to the cell's source lines. When called from a scratch
	edit buffer (see |:EuropaEditCell|), the cursor line maps directly
	to the source.

	The upper cell retains the original cell ID, outputs, and
	execution_count. The lower cell gets a new UUID and empty outputs.

	See also: |:EuropaJoinCell|, |<Plug>(europa-split-cell)|

							*:EuropaJoinCell*
:EuropaJoinCell
	Join the cell at cursor with the cell immediately above it. The
	surviving cell retains the upper cell's ID, type, outputs, and
	execution_count. Sources are concatenated with a newline separator.

	No-op if cursor is on the first cell.

	See also: |:EuropaSplitCell|, |<Plug>(europa-join-cell)|

							*:EuropaEditCell*
:EuropaEditCell
	Open the source of the cell at cursor in a scratch buffer named
	`__europa_cell_<id>__`. The scratch buffer has `buftype=acwrite`
	so that `:write` commits the edited source back to the notebook
	and re-renders the viewer.

	A second call on the same cell reuses the existing scratch buffer
	(`:buffer <scratchBufnr>`).

	See also: |:EuropaSplitCell|, |<Plug>(europa-edit-cell)|

							*:EuropaCellType*
:EuropaCellType {type}
	Change the type of the cell at cursor to {type} (`code`, `markdown`,
	or `raw`).

	  code → markdown/raw: `outputs` and `execution_count` fields are
	                        removed from the cell.
	  markdown/raw → code: `outputs` and `execution_count` are
	                        initialized to `[]` and `null`.

	If a scratch edit buffer is open for the cell, its `filetype` is
	updated to match the new cell type.

	See also: |:EuropaEditCell|

MAPPINGS						*europa-mappings*

Europa.vim does NOT install any default key mappings. You must bind the
`<Plug>(europa-*)` handles to keys of your choice.

PLUG MAPPINGS~
							*europa-plug-mappings*

					     *<Plug>(europa-insert-code)*
					 *<Plug>(europa-insert-markdown)*
					      *<Plug>(europa-insert-raw)*
					      *<Plug>(europa-delete-cell)*
					        *<Plug>(europa-cell-up)*
					      *<Plug>(europa-cell-down)*
					        *<Plug>(europa-edit-cell)*
					       *<Plug>(europa-split-cell)*
					        *<Plug>(europa-join-cell)*

The following `<Plug>` mappings are defined in `plugin/mappings.vim`:

    <Plug>(europa-insert-code)      Insert a new code cell after cursor
    <Plug>(europa-insert-markdown)  Insert a new markdown cell after cursor
    <Plug>(europa-insert-raw)       Insert a new raw cell after cursor
    <Plug>(europa-delete-cell)      Delete the cell at cursor
    <Plug>(europa-cell-up)          Move the cell at cursor one position up
    <Plug>(europa-cell-down)        Move the cell at cursor one position down
    <Plug>(europa-edit-cell)        Open scratch buffer for the cell at cursor
    <Plug>(europa-split-cell)       Split the cell at cursor at the current line
    <Plug>(europa-join-cell)        Join the cell at cursor with the one above

Note: `:EuropaCellType {type}` and `:EuropaInsertCell! {type}` (insert before)
are not exposed as `<Plug>` mappings because they require arguments and are
best invoked from the command line.

RECOMMENDED BINDINGS~
					     *europa-recommended-mappings*

Place the following in `~/.vim/after/ftplugin/europa.vim` (or the Neovim
equivalent) to bind the mappings for notebook buffers: >

    nmap <buffer><silent> <localleader>ic <Plug>(europa-insert-code)
    nmap <buffer><silent> <localleader>im <Plug>(europa-insert-markdown)
    nmap <buffer><silent> <localleader>dc <Plug>(europa-delete-cell)
    nmap <buffer><silent> <localleader>ec <Plug>(europa-edit-cell)
    nmap <buffer><silent> <localleader>cu <Plug>(europa-cell-up)
    nmap <buffer><silent> <localleader>cd <Plug>(europa-cell-down)
    nmap <buffer><silent> <localleader>sc <Plug>(europa-split-cell)
    nmap <buffer><silent> <localleader>jc <Plug>(europa-join-cell)
<

EXAMPLES						*europa-examples*

BASIC VIEWING~
						*europa-examples-viewing*
Open a notebook and browse its cells: >
	:edit ~/projects/analysis.ipynb
<
The buffer renders each cell with Unicode borders. Code cells show their
source and any captured outputs. Markdown cells show the source text with
heading lines highlighted. Use standard Vim motion keys to navigate.

PREVIEWING AN IMAGE OUTPUT~
					*europa-examples-preview*
When a cell contains an image output the buffer shows a placeholder line: >
	[image: png 640x480 - :EuropaPreviewOutput 2 0]
<
The two numbers are the cell index and output index (both zero-based). Run
the embedded command to open the image in the system viewer: >
	:EuropaPreviewOutput 2 0
<

SAVING A NOTEBOOK~
					*europa-examples-save*
`:write` serialises the in-memory notebook back to disk in canonical
`.ipynb` format (1-space indent, trailing newline): >
	:write
<
The round-trip is semantic: `parse(serialize(parse(x)))` equals `parse(x)`
for all well-formed notebooks.

SIXEL INLINE IMAGES (EXPERIMENTAL)~
					*europa-examples-sixel*
On a Sixel-capable terminal (e.g. WezTerm) with ImageMagick installed,
add to your vimrc: >
	let g:europa_image_backend = 'sixel'
<
Then open a notebook that contains image outputs. If ImageMagick is not
found, or if conversion fails, the plugin falls back to the text placeholder
and prints a message in `:messages`.

FREQUENTLY ASKED QUESTIONS				*europa-faq*

WHY IS THE BUFFER READ-ONLY?~
						*europa-faq-readonly*
Phase 2 is a viewer. Europa intercepts `BufReadCmd` and sets
`modifiable=false` so keystrokes do not corrupt the internal notebook state.
Cell editing lands in Phase 3.

WHY DOES SIXEL FALL BACK TO THE PLACEHOLDER?~
					*europa-faq-sixel-fallback*
Several conditions cause the Sixel path to skip and show the text placeholder:

1. ImageMagick (`magick` or `convert`) is not found on PATH.
2. The image payload could not be decoded (corrupt base64).
3. The conversion subprocess returned a non-zero exit code.
4. The placeholder line was scrolled off-screen when rendering ran
   (`screenpos()` returned row 0).

Run `:messages` to see which condition triggered. If ImageMagick is installed
but not found, check that it is on the PATH Vim/Neovim uses (which may differ
from your shell PATH).

SIXEL DOES NOT WORK IN TMUX~
					*europa-faq-tmux*
The standard tmux 3.6a build does not forward Sixel graphics. You need a
build compiled with `--enable-sixel`, or tmux 3.4+ with `allow_passthrough
on` in `tmux.conf`. Ghostty 1.3.1 is also not confirmed to work in Phase 2.

WHY ARE IMAGES OVERLAPPING TEXT AFTER SCROLLING?~
					*europa-faq-sixel-overlap*
Sixel graphics are drawn as a separate graphics layer over the text grid.
Europa reserves spacer rows below each image placeholder to prevent overlap,
and skips rendering when the anchor line is off-screen. If overlap still
occurs, try reducing |g:europa_lazy_padding| or upgrading to a terminal that
clips the Sixel graphics layer correctly.

WHY DOES `:write` CHANGE THE FILE FORMAT?~
					*europa-faq-write*
`:write` normalises the notebook to 1-space indent JSON with a trailing
newline — the canonical format used by `nbformat`. The content is
semantically identical to the original; only whitespace and key ordering may
change. Subsequent writes produce no further diff.
