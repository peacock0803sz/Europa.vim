==============================================================================
SYNTAX HIGHLIGHT					*europa-syntax-highlight*

Europa can apply native tree-sitter syntax highlighting to code and Markdown
cell content inside `.ipynb` buffers. The feature uses Neovim's built-in
`vim.treesitter` API (Neovim 0.11.3+) and requires the relevant language
parsers to be installed (e.g. via `nvim-treesitter`). On Vim hosts the
feature is a no-op; existing border highlights are preserved unchanged.

CONFIGURATION~
					*europa-syntax-highlight-config*

*g:europa_ts_highlight*
	Controls tree-sitter syntax highlighting for cell content.
	Type: string  Default: `'auto'`

	`'auto'`	Enable highlighting when Neovim's `vim.treesitter` runtime
			is available AND the relevant language parsers are installed.
			Falls back silently to no-op on Vim or when parsers are
			absent.
	`'on'`		Force-enable. Highlighting is attempted regardless of
			capability detection. Individual cells whose parsers are
			missing are skipped silently (FR-006).
	`'off'`		Disable all tree-sitter cell highlighting. Useful when
			performance is a concern or when testing the plain viewer.

	Example (init.lua): >lua
	  vim.g.europa_ts_highlight = 'on'
<
	Example (vimrc): >vim
	  let g:europa_ts_highlight = 'off'
<

HIGHLIGHT GROUPS~
					*europa-syntax-highlight-groups*

Cell content highlights come from the standard `@capture.name` groups
produced by `vim.treesitter.query.get(lang, 'highlights')`. Europa does not
define any color-bearing groups of its own for cell content; all colors come
from the active colorscheme via its tree-sitter integration (FR-005).

The following execution-state indicator groups are defined for code cells and
are linked to standard groups by default:

	*EuropaCellBusyHl*	Linked to `WarningMsg`. Cell is executing.
	*EuropaCellQueuedHl*	Linked to `Comment`. Cell is queued.
	*EuropaCellAbortedHl*	Linked to `ErrorMsg`. Cell execution was aborted.

Override any of these in your colorscheme or vimrc: >vim
	hi! link EuropaCellBusyHl DiffChange
<

SUPPORTED LANGUAGES~
				*europa-syntax-highlight-languages*

Any language with a tree-sitter parser installed in Neovim is supported for
code cells. The language is resolved from the notebook's kernel metadata:

1. `metadata.kernelspec.language`
2. `metadata.language_info.name`
3. Plain text (no highlighting applied)

Markdown cells are highlighted as `markdown`. If the `markdown` and
`markdown_inline` parsers are installed, code fences (e.g. ` ```python `)
are highlighted using the fenced language's parser via tree-sitter injection
queries (`injections.scm`). Missing injection parsers fail silently (FR-006).

TROUBLESHOOTING~
				*europa-syntax-highlight-troubleshooting*

Color is not appearing for code cells~
1. Check `g:europa_ts_highlight` is not set to `'off'`.
2. Verify you are on Neovim 0.11.3+: `:echo has('nvim-0.11.3')` must return 1.
3. Check the language parser is installed: `:checkhealth nvim-treesitter`
   (if using nvim-treesitter) or `:lua vim.treesitter.language.require_language('python')`.
4. Force-enable with `:let g:europa_ts_highlight = 'on'` and re-open the file.

Vim host shows no cell content highlighting~
This is expected. Europa's tree-sitter feature requires Neovim's native
`vim.treesitter` API and is intentionally a no-op on Vim. Cell borders and
execution-state signs are still active on Vim.
