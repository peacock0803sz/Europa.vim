==============================================================================
CONFIGURATION						*europa-configuration*

All options are global Vim variables of the form `g:europa_*`. Set them in
your vimrc or init.lua before the plugin loads. Unset options fall back to
the defaults shown below.

RENDERING OPTIONS~
					*europa-configuration-rendering*

*g:europa_image_backend*
	Controls how image outputs are displayed.
	Type: string  Default: `'auto'`

	`'auto'`	Resolves to `'placeholder'` in Phase 2. Terminal
			auto-detection (DA1 query) is added in Phase 3.
	`'placeholder'`	Shows a `[image: png WxH - :EuropaPreviewOutput N M]`
			line. Works in every terminal.
	`'sixel'`	Experimental. Renders images inline via ImageMagick.
			Requires a Sixel-capable terminal and ImageMagick on
			PATH. Falls back to placeholder when either is absent.
	`'kitty_placeholder'`  Reserved for Phase 3.
	`'iterm2_osc1337'`     Reserved for Phase 3.

*g:europa_mime_priority*
	MIME type preference order for outputs that carry multiple
	representations (display_data / execute_result).
	Type: list of strings
	Default: `['image/png', 'image/jpeg', 'text/html', 'text/plain']`

*g:europa_max_output_lines*
	Maximum lines rendered per cell output. Outputs that exceed this
	limit are truncated with a `[... truncated, N more lines]` note.
	Type: integer  Default: `100`

*g:europa_cell_border_chars*
	Unicode strings used to draw cell borders, in order:
	top-left corner, horizontal fill, top-right corner,
	bottom-left corner, bottom-right corner.
	The first character of `chars[0]` and `chars[3]` is also
	used by `syntax/europa.vim` to detect header/footer lines
	for highlighting; if you set custom values, the syntax
	regex picks them up automatically on next buffer open.
	Note: changing this option mid-session requires `:e` (buffer
	re-open) to refresh the syntax highlighting regex.
	Type: list of exactly 5 non-empty strings
	Default: `['╭', '─', '╮', '╰', '╯']`

*g:europa_cell_border_padding*
	Number of horizontal fill characters (`chars[1]`) used per side in
	center-aligned mode, or placed entirely on the right in left-aligned
	mode. A value of `4` with `'left'` produces `╭ In [1] ────────╮`;
	the same value with `'center'` produces `╭──── In [1] ────╮`.
	`0` omits the fill regardless of alignment, yielding `╭ In [1] ╮`.
	Type: integer (minimum: 0)  Default: `4`

*g:europa_cell_border_align*
	Horizontal alignment of the label within the cell border line.
	`'left'`	Label immediately after the corner: `╭ In [1] ────────╮`
	`'center'`	Label centered with equal fill on both sides:
			`╭──── In [1] ────╮`
	Type: string (`'left'` or `'center'`)  Default: `'left'`

*g:europa_lazy_padding*
	Lines above and below the visible viewport that are pre-rendered
	on open. Larger values trade startup time for smoother scrolling.
	Type: integer  Default: `10`

BEHAVIOUR OPTIONS~
					*europa-configuration-behaviour*

*g:europa_auto_save*
	When `v:true`, write the notebook back to disk automatically on
	`BufLeave`. Not recommended until Phase 3 adds conflict detection.
	Type: boolean  Default: `v:false`

*g:europa_use_default_mappings*
	Reserved for Phase 3. No default mappings are provided in Phase 2.
	Type: boolean  Default: `v:false`

CONNECTION OPTIONS~
					*europa-configuration-connection*

Europa connects to a kernel two ways.  The options below configure server mode
(a Jupyter server, reached via |:EuropaStartKernel|).  For a direct ZeroMQ attach
to an externally-started kernel, use |:EuropaAttach| with the kernel's connection
file; it needs no server and ignores the options below.

|:EuropaAttach| is the only attach entrypoint in this phase.  Automatic routing
via a `g:europa_connection_mode` heuristic is reserved for a later slice and is
not implemented yet.

*g:europa_use_subprocess*
	Whether europa spawns a local Jupyter Server subprocess or connects
	to an already-running server.
	Type: boolean  Default: `v:true`

	`v:true`	Subprocess mode. Europa starts `jupyter server` via the
			watchdog wrapper and manages its lifecycle.  The
			executable is located with |g:europa_jupyter_executable|
			or the 6-priority auto-detect chain (see
			|g:europa_python_env_detect|).
	`v:false`	Attach mode. Europa connects to the URL given by
			|g:europa_jupyter_url|.  A token must be set via
			|g:europa_jupyter_token| or `$JUPYTER_TOKEN`.
			Europa never kills the external server on shutdown;
			only the WebSocket and REST session are cleaned up.

	Example — attach to an existing server started externally: >
		" In terminal A:
		"   jupyter server --port=9999 --ServerApp.token=mytoken
		let g:europa_use_subprocess = v:false
		let g:europa_jupyter_url = 'http://localhost:9999'
		let g:europa_jupyter_token = 'mytoken'
<

*g:europa_jupyter_url*
	Base URL of the Jupyter server used in attach mode
	(|g:europa_use_subprocess| = `v:false`).
	Type: string  Default: `'http://localhost:8888'`

*g:europa_jupyter_token*
	Authentication token for Jupyter Server REST/WebSocket requests.
	Type: string  Default: `''`

	Token resolution order:
	  1. `g:europa_jupyter_token` (this option)
	  2. `$JUPYTER_TOKEN` environment variable
	  3. Random 32-char hex (subprocess mode only, generated at startup)
	  Attach mode raises an error if steps 1-2 are both empty.

*g:europa_jupyter_ws_subprotocol*
	WebSocket subprotocol negotiation mode.
	Type: string  Default: `'auto'`

	`'default'`	Text JSON subprotocol only (widest compatibility).
	`'v1'`		Binary v1 subprotocol only (offset-table frame layout).
	`'auto'`	Offer all three subprotocols; server picks the best.
			Requires JupyterLab-style server >= 2.x.

*g:europa_default_kernel*
	Kernel name used when |:EuropaStartKernel| is called without an
	argument, and for |g:europa_auto_start_kernel|.
	Type: string  Default: `'python3'`

*g:europa_auto_start_kernel*
	When `v:true`, automatically call |:EuropaStartKernel| after a
	notebook buffer is opened (via a zero-delay timer so the buffer is
	fully loaded first).
	Type: boolean  Default: `v:false`

*g:europa_jupyter_executable*
	Absolute path to the `jupyter` (or `jupyter.exe`) binary.  When set,
	overrides all auto-detection (step 1 of the 6-priority chain).
	Type: string  Default: `''` (auto-detect)

*g:europa_python_env_detect*
	Controls which steps of the 6-priority Jupyter executable detection
	chain are active (DESIGN.md §6.5).
	Type: string  Default: `'auto'`

	`'auto'`	Full detection chain (6 steps):
			  1. |g:europa_jupyter_executable| (explicit override)
			  2. `{cwd}/.venv/bin/jupyter`  (Windows: `Scripts\jupyter.exe`)
			  3. `{cwd}/venv/bin/jupyter`   (Windows: `Scripts\jupyter.exe`)
			  4. `$VIRTUAL_ENV/bin/jupyter`
			  5. `$CONDA_PREFIX/bin/jupyter`
			  6. `which jupyter` on PATH    (Windows: `where jupyter`)
	`'disabled'`	Skip steps 2-5; use only step 1 (explicit override)
			or step 6 (PATH / `where`).

*g:europa_ws_reconnect_max_retries*
	Maximum number of WebSocket reconnect attempts before giving up.
	Type: integer  Range: 0-20  Default: `5`

	Set to `0` to disable reconnection entirely.

*g:europa_ws_reconnect_initial_interval_ms*
	Initial delay in milliseconds before the first reconnect attempt.
	Subsequent attempts use exponential backoff controlled by
	|g:europa_ws_reconnect_multiplier|.
	Type: integer  Range: 100-30000  Default: `1000`

*g:europa_ws_reconnect_multiplier*
	Backoff multiplier applied to the reconnect interval after each
	failed attempt.  A value of `2.0` doubles the interval each time.
	Type: float  Range: 1.0-4.0  Default: `2.0`

						*g:europa_undo_max_history*
g:europa_undo_max_history
	Maximum number of undo entries retained per ft=europa buffer.
	Entries are evicted in FIFO order when the limit is exceeded (oldest
	mutation is dropped first).

	Values outside the range [10, 1000] are rejected with an error at
	startup (EuropaConfigError).

	Type: integer  Range: 10-1000  Default: `100`

	Example: >
	  let g:europa_undo_max_history = 200
<

					*g:europa_disable_default_mappings*
g:europa_disable_default_mappings
	When set to `v:true`, `ftplugin/europa.vim` does not bind `u` or
	`<C-r>` to |<Plug>(europa-undo)| / |<Plug>(europa-redo)|.  The
	`<Plug>` mappings and |:EuropaUndo| / |:EuropaRedo| commands remain
	available for custom bindings.

	Type: boolean  Default: `v:false`

	Example: >
	  let g:europa_disable_default_mappings = v:true
	  nmap <buffer><silent> <leader>u <Plug>(europa-undo)
	  nmap <buffer><silent> <leader>r <Plug>(europa-redo)
<

					*g:europa_lsp_enable*
g:europa_lsp_enable
	Controls the LSP-ready notebook mirror used by |:EuropaEditCell|
	(Phase 3.9).  When enabled for a python notebook, `:EuropaEditCell`
	edits a single on-disk `.py` "notebook mirror" (all code cells
	concatenated, one per `# %% <cellId>` region) instead of a per-cell
	scratch buffer.  Your existing LSP client (pyright / ruff / ty) then
	attaches to that real file, and symbols defined in an upper cell
	resolve from a lower cell (cross-cell).

	  "auto"    Enable only for python notebooks (default).
	  v:true    Force-enable for python notebooks; a non-python notebook
		    still falls back to the scratch buffer.
	  v:false   Disable; use the classic per-cell scratch buffer.

	Type: string|boolean  Default: `"auto"`

	Europa is client-agnostic: it only provides the mirror file, a
	workspace root, and `filetype=python`.  There is deliberately NO
	client-selection option -- configure pyright / ruff / ty in your own
	LSP client (vim-lsp, nvim-lspconfig, coc.nvim, or the Neovim built-in
	client).  See |europa-setup-lsp| for client examples.

	The mirror is written under `<workspace-root>/.europa/lsp/` (or a
	per-session cache dir for unsaved notebooks) and removed when the
	buffer is wiped.  Add `.europa/` to your project's `.gitignore`.

	Example: >
	  let g:europa_lsp_enable = v:false
<
