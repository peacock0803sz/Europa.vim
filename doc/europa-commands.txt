==============================================================================
COMMANDS						*europa-commands*

							*:EuropaOpen*
:EuropaOpen [path]
	Open {path} as a Europa viewer buffer. When {path} is omitted the
	current file (`%`) is used. The buffer is set to `modifiable=false`
	and `conceallevel=0`.

	This command is also triggered automatically by `BufReadCmd` when
	you open any `*.ipynb` file with `:edit`.

							*:EuropaPreviewOutput*
:EuropaPreviewOutput {cellIdx} {outputIdx}
	Write the image output at cell index {cellIdx} and output index
	{outputIdx} to a temporary file and open it with the OS default
	image viewer:
	  macOS   `open`
	  Linux   `xdg-open`
	  Windows `cmd /c start`

	Both arguments are zero-based integers. The placeholder line in the
	buffer shows the exact command to run, for example: >
	  [image: png 640x480 - :EuropaPreviewOutput 3 0]
<
	Only image MIME types (`image/png`, `image/jpeg`) are supported.
	Calling this command on a non-image output prints a message and does
	nothing.

CELL EDITING COMMANDS~
						*europa-commands-editing*

							*:EuropaInsertCell*
:EuropaInsertCell {type} [{position}]
	Insert a new empty cell of {type} (`code`, `markdown`, or `raw`)
	relative to the cell at cursor. {position} is `before` or `after`
	(default `after`).

	:EuropaInsertCell! {type}
		Equivalent to `:EuropaInsertCell {type} before`.

	Example: >
	  :EuropaInsertCell code
	  :EuropaInsertCell markdown after
	  :EuropaInsertCell! raw
<
	See also: |:EuropaDeleteCell|, |:EuropaCellType|,
	          |<Plug>(europa-insert-code)|

							*:EuropaDeleteCell*
:EuropaDeleteCell
	Delete the cell at the cursor position. If this is the last cell,
	the viewer shows an empty-notebook guidance message.

	See also: |:EuropaInsertCell|, |<Plug>(europa-delete-cell)|

						*:EuropaMoveCellUp*
:EuropaMoveCellUp
	Swap the cell at cursor with the cell immediately above it in the
	notebook. No-op with a guidance message if already at the top.

	See also: |:EuropaMoveCellDown|, |<Plug>(europa-cell-up)|

						*:EuropaMoveCellDown*
:EuropaMoveCellDown
	Swap the cell at cursor with the cell immediately below it in the
	notebook. No-op with a guidance message if already at the bottom.

	See also: |:EuropaMoveCellUp|, |<Plug>(europa-cell-down)|

							*:EuropaSplitCell*
:EuropaSplitCell
	Split the cell at cursor into two cells at the current line.

	When called from a viewer buffer, the split point is resolved
	relative to the cell's source lines. When called from a scratch
	edit buffer (see |:EuropaEditCell|), the cursor line maps directly
	to the source.

	The upper cell retains the original cell ID, outputs, and
	execution_count. The lower cell gets a new UUID and empty outputs.

	See also: |:EuropaJoinCell|, |<Plug>(europa-split-cell)|

							*:EuropaJoinCell*
:EuropaJoinCell
	Join the cell at cursor with the cell immediately above it. The
	surviving cell retains the upper cell's ID, type, outputs, and
	execution_count. Sources are concatenated with a newline separator.

	No-op if cursor is on the first cell.

	See also: |:EuropaSplitCell|, |<Plug>(europa-join-cell)|

							*:EuropaEditCell*
:EuropaEditCell
	Open the source of the cell at cursor in a scratch buffer named
	`__europa_cell_<id>__`. The scratch buffer has `buftype=acwrite`
	so that `:write` commits the edited source back to the notebook
	and re-renders the viewer.

	A second call on the same cell reuses the existing scratch buffer
	(`:buffer <scratchBufnr>`).

	See also: |:EuropaSplitCell|, |<Plug>(europa-edit-cell)|

							*:EuropaCellType*
:EuropaCellType {type}
	Change the type of the cell at cursor to {type} (`code`, `markdown`,
	or `raw`).

	  code → markdown/raw: `outputs` and `execution_count` fields are
	                        removed from the cell.
	  markdown/raw → code: `outputs` and `execution_count` are
	                        initialized to `[]` and `null`.

	If a scratch edit buffer is open for the cell, its `filetype` is
	updated to match the new cell type.

	See also: |:EuropaEditCell|

KERNEL COMMANDS~
					*europa-kernel-commands*

							*:EuropaStartKernel*
:EuropaStartKernel [{name}]
	Start or connect to a Jupyter kernel for the current buffer.

	{name} is the kernel name to start (e.g. `python3`, `ir`).  When
	{name} is omitted the value of |g:europa_default_kernel| is used
	(default: `python3`).

	The command is asynchronous: it returns immediately and the kernel
	connection is established in the background.  Progress and errors
	are reported via |:messages| (e.g. `EuropaKernelError: ...`).

	Example — explicit kernel name: >
		:EuropaStartKernel python3
<	Example — use default kernel: >
		:EuropaStartKernel
<	Example — attach to an existing server (set in vimrc first): >
		let g:europa_use_subprocess = v:false
		let g:europa_jupyter_url = 'http://localhost:9999'
		let g:europa_jupyter_token = 'mytoken'
<	Then run `:EuropaStartKernel python3` as normal.  Europa connects
	to the running server without spawning a subprocess.

	See also: |g:europa_default_kernel|, |g:europa_jupyter_url|,
	|g:europa_use_subprocess|

							*:EuropaShutdownKernel*
:EuropaShutdownKernel
	Shut down the kernel attached to the current buffer and release its
	server-side session.

	The command is asynchronous: it returns immediately and kernel teardown
	proceeds in the background.  Progress and errors are reported via
	|:messages|.

	Cleanup is automatic on three other paths:
	  - `:bwipeout` of the notebook buffer fires the `BufWipeout` autocmd,
	    which shuts down the attached kernel as part of buffer cleanup.
	  - Quitting Vim (`:qa!`, normal exit) fires `VimLeavePre`, which shuts
	    down every active kernel via the `atexit` dispatcher.
	  - If Vim is killed with SIGKILL, the watchdog subprocess detects the
	    parent's death and kills the Jupyter server process within 15 s.

	When `g:europa_use_subprocess = v:false` (external server mode), the
	session DELETE is sent but the Jupyter server process is not killed.

	See also: |:EuropaStartKernel|, |g:europa_use_subprocess|

							*:EuropaKernelStatus*
:EuropaKernelStatus
	Display the current kernel connection status for the buffer in
	|:messages|.

	When a kernel is attached, the output includes:
	  - Kernel name and kernel ID
	  - Kernel execution state (`starting`, `idle`, `busy`,
	    `reconnecting`, or `disconnected`) and WebSocket state
	  - Reconnection progress (`retry: 2/5`) when reconnecting
	  - Language name and version (from the kernel_info_reply)
	  - Server reference count (number of buffers sharing the process)

	When no kernel is attached: >
	    Europa: No kernel attached to this buffer.
	    Use :EuropaStartKernel to start one.
<
	All four connection states (before start, connected, reconnecting,
	disconnected) are handled without crashing (SC-011).

	See also: |:EuropaStartKernel|, |:EuropaShutdownKernel|

							*:EuropaCommStatus*
:EuropaCommStatus
	List every open Jupyter comm for the kernel attached to the current
	buffer. The output is a four-column table written with `:echo` (it does
	not persist into |:messages| because the snapshot is transient debug
	output, not a status report).

	Output columns:
	  - COMM_ID — first 8 characters of the UUID-shaped identifier
	  - TARGET_NAME — protocol identifier (`jupyter.widget`,
	    `europa.test.echo`, etc.)
	  - OPENER — `kernel` if the kernel initiated the open,
	    `frontend` if Europa called the openComm API
	  - AGE(s) — integer seconds since the comm was opened

	When the buffer has no kernel attached, prints `No kernel attached.`
	When a kernel is attached but no comm is open, prints `No open comms.`

	Intended as a Phase 5.1 debug aid before higher-level widget UIs land.
	Sample output: >
	    COMM_ID    TARGET_NAME                       OPENER      AGE(s)
	    3f7a8b2c   europa.test.echo                  kernel          12
	    9d1e2f4a   jupyter.widget                    frontend         3
<
	See also: |europa-kernel-comm|

KERNEL EXECUTION COMMANDS~
					*europa-commands-execution*

							*:EuropaRunCell*
:EuropaRunCell
	Execute the code cell at the cursor position.

	The cell source is snapshotted at call time (edits made while the kernel
	is busy do not affect the in-flight request). Outputs are appended after
	the kernel replies. The sign column shows `*` (busy) or `…` (queued).

	Non-code cells (markdown, raw) produce a warning and are not executed.

	See also: |<Plug>(europa-run-cell)|, |:EuropaInterrupt|

							*:EuropaRunAll*
:EuropaRunAll
	Execute all code cells in the buffer sequentially from top to bottom.

	Markdown and raw cells are skipped. An error reply cancels the remaining
	queued cells and prints: `"Run all stopped at cell N/M due to error"`.
	Use |:EuropaCancelCell| to drop individual cells before they execute.

	See also: |<Plug>(europa-run-all)|, |:EuropaCancelCell|

							*:EuropaInterrupt*
:EuropaInterrupt
	Send a REST interrupt request to the kernel (SIGINT equivalent).

	The running cell receives `KeyboardInterrupt`; the traceback is appended
	to the cell outputs. Calling this while idle shows an informational
	message without raising an error.

	See also: |<Plug>(europa-interrupt)|, |:EuropaRestartKernel|

							*:EuropaRestartKernel*
:EuropaRestartKernel
	Restart the kernel, clearing all variables.

	Sequence: abort pending execute → REST `POST /restart` → close old
	WebSocket → open new WebSocket → `kernel_info_request` / `kernel_info_reply`
	re-handshake. All cell `execution_count` fields reset to `null`. Completes
	within 10 s on a local server (SC-004). On REST failure the old
	WebSocket stays open so the kernel remains usable.

	See also: |<Plug>(europa-restart-kernel)|, |:EuropaInterrupt|

							*:EuropaCancelCell*
:EuropaCancelCell
	Drop the queued cell at the cursor from the pending-requests queue.

	Only `queued` cells (not yet sent to the kernel) can be cancelled; `busy`
	cells require |:EuropaInterrupt|. No network message is sent.

	See also: |<Plug>(europa-cancel-cell)|, |:EuropaRunAll|

							*:EuropaUndo*
:EuropaUndo
	Roll back the most recent structural mutation in the current ft=europa
	buffer.  Equivalent to pressing `u` when |g:europa_disable_default_mappings|
	is not set.

	Operates on cell-level operations (insert, delete, move, split, join,
	change-type, edit).  Kernel outputs and execution counts are preserved
	across undo (they are intentionally not included in the undo snapshot).

	The undo history is per-buffer and reset when the buffer is wiped out.
	Stack depth is controlled by |g:europa_undo_max_history| (default 100).

	See also: |:EuropaRedo|, |<Plug>(europa-undo)|

							*:EuropaRedo*
:EuropaRedo
	Re-apply the most recently undone structural mutation in the current
	ft=europa buffer.  Equivalent to pressing `<C-r>` when
	|g:europa_disable_default_mappings| is not set.

	The redo stack is cleared whenever a new mutation is committed (matching
	Vim's native undo behaviour).

	See also: |:EuropaUndo|, |<Plug>(europa-redo)|

TRACEBACK NAVIGATION COMMANDS~
					*europa-commands-traceback*

							*:EuropaJumpError*
:EuropaJumpError
	Jump to the source line referenced by the IPython 8.x traceback
	frame under the cursor. Two frame shapes are recognised:

	  `Cell In[N], line K`   → cursor moves to line K of the code cell
	                           whose `execution_count == N`. The
	                           viewport is centered with `zz`.
	  `File /path:K`         → opens `/path` in a `:split` and moves
	                           the cursor to line K (also `zz`).
	                           Relative paths are resolved against
	                           the kernel's working directory; `~` is
	                           HOME-expanded.

	Silently no-ops when:
	  - the cursor is not on a traceback frame range,
	  - the referenced cell does not exist (e.g. it was deleted),
	  - K is outside the cell's source range.

	When the viewer buffer is hidden, the command warns once via
	`:echom` and stores `b:europa_jump_warned = 1` so repeated invocations
	stay silent. `BufWinEnter` resets the flag, so re-showing the buffer
	re-arms the warning for the next attempt.

	When the cell exists but is not actionable (missing or K-out-of-
	range), the frame's underline switches from |hl-EuropaErrorJump|
	to |hl-EuropaErrorJumpMissing| (the `Comment` link by default)
	so you can tell at a glance which frames can be navigated to.

	Relative `File ./...:K` frames resolve against the kernel's
	working directory when a kernel is attached. Without an attached
	kernel the dispatcher falls back to `nvim`'s launch directory so
	the smoke walkthrough against
	`tests/fixtures/ipynb/error-external-file.ipynb` works when
	`nvim` is started from the repo root.

	See also: |<Plug>(europa-jump-error)|, |:EuropaJumpErrorList|

							*:EuropaJumpErrorList*
:EuropaJumpErrorList
	Populate the |quickfix-list| with every actionable IPython 8.x
	traceback frame from the latest RenderPlan and set the qflist
	title to "Europa traceback".

	The command does NOT call `:copen`: it only writes the list so
	you can decide whether to open the window with your own
	`:copen` / `:cwindow` / quickfix-plugin workflow. Once populated,
	standard Vim motions (`:cnext`, `:cprev`, `:cfirst`, `:clast`)
	walk between frames.

	Actionable filter:
	  - `Cell In[N], line K` is included when a code cell with
	    `execution_count == N` exists AND `K` is within the cell's
	    source range. Otherwise the frame is skipped.
	  - `File ...` frames are always included; non-existent files
	    surface Vim's standard `E:Cannot find file` when you jump
	    to them.

	When the viewer is hidden, the command warns once via `:echom`
	(same `b:europa_jump_warned` guard as |:EuropaJumpError|) and
	is silent on repeated invocations until `BufWinEnter` re-arms
	the flag.

	See also: |<Plug>(europa-jump-error-list)|, |:EuropaJumpError|,
	|quickfix|
